# Frozen local-demo credential protocol v2

Status: wire specification frozen; executable interoperability gate pending a
permitted Go execution environment. No RA issuance or Voting API is implemented
by this milestone. This specification supersedes the credential-message layouts
in Documents 07 section 4 and 08 section 7; their database history is unchanged.

## Profile

RFC 9474 RSABSSA-SHA384-PSS-Randomized, RSA-3072, e=65537, SHA-384,
MGF1-SHA-384, exactly 48 bytes of PSS salt, and exactly 32 bytes of randomized
Prepare prefix. No fallback or algorithm negotiation. Blind inputs and outputs
and final signatures are exactly 384 bytes. CSPRNGs supply serial, prefix, salt,
and blinding randomness through the established implementation.

- Client: @cloudflare/blindrsa-ts 0.4.6.
- Blind signer: github.com/cloudflare/circl v1.6.5.
- Python public verification: cryptography 50.0.2.
- RFC 8785 serialization: canonicalize 5.1.0 (TypeScript), rfc8785 0.1.4 (Python).

An ordinary RSA-PSS signing call is not BlindSign. The only blind signing call in
the Go test signer is CIRCL `BlindSign(original_blinded_bytes)`. SHA256 of those
bytes is only an equality/diagnostic hash; it is never the signing input. A
32-byte digest is rejected because it is not a modulus-sized blinded message.
No application RSA private exponentiation is implemented.

## Exact credential message

Exactly these fields are required; unknown or missing fields are rejected:

| Field | Type and fixed rule |
|---|---|
| domain | string, exactly secure-evoting-blind-credential-v2 |
| version | integer, exactly 2; booleans and string coercions forbidden |
| election_id | string, canonical lowercase hyphenated UUID |
| serial | string, canonical unpadded base64url of 32 CSPRNG bytes generated by client |
| envelope_hash | string, 64 lowercase hexadecimal characters |
| config_hash | string, 64 lowercase hexadecimal characters |
| key_id | string matching `[a-z0-9][a-z0-9._-]{0,127}` exactly |

`envelope_hash = SHA256(JCS(encrypted_envelope))`.
`config_hash = SHA256(JCS(verified_manifest))`, excluding its detached signature.
`key_id` must equal the verified manifest's RA key identifier. The RSA verification
key must be selected from that manifest, never from an unsigned request.
An expected election ID is supplied independently of the manifest response.

`M = UTF8(RFC8785-JCS(message))`.
`prepared_msg = random_prefix_32_bytes || M` using the library Prepare function.
Client invokes Blind on those prepared bytes with the manifest's public key.
After receiving a blind signature it invokes Finalize and verifies the result.
Voting verifies PSS over **the entire prepared_msg**, with salt_length=48,
and requires `prepared_msg[32:] == M` reconstructed from validated bindings.

The anonymous proof envelope has exactly `message`, `prepared_msg`, `signature`.
The latter two are canonical unpadded base64url. This is the crypto proof format;
future ballot APIs also have to recompute envelope_hash from the actual envelope.
No voter_id, username, RA session token, or issuance request_id is permitted.

Canonical base64url requires decode/re-encode equality, correct byte length,
URL-safe alphabet, no padding/whitespace, and zero unused trailing bits. JSON
decoding must reject duplicate keys and invalid UTF-8. Signed message bytes must
match RFC 8785 exactly, with no BOM, trailing bytes, or silent normalization.
The committed [serialization vectors](../crypto_interop/vectors/credential-v2.json)
contain public example messages and literal canonical UTF-8 expectations.

## Independently trusted local manifest authority

A separate Ed25519 signing authority signs immutable manifests. Its key must be
distinct from RA blind signing and Tally encryption keys. The authority signs:

`UTF8("EVOTE-MANIFEST-v1") || 0x00 || JCS(manifest)`.

The detached bundle has exactly `manifest` and `signature` (base64url, 64 bytes).
The authority's raw 32-byte public key is pinned through an operator-controlled
channel independently of the API. A root key included by the API is not accepted.
The verification function takes the pin as a separate trusted argument.

The manifest has exactly:

| Field | Type/rule |
|---|---|
| domain | string, secure-evoting-election-manifest-v1 |
| version | integer, 1 |
| election_id | canonical UUID matching the independently selected election |
| opens_at, closes_at | UTC strings `YYYY-MM-DDTHH:MM:SSZ`, valid dates, opens_at < closes_at |
| candidates | nonempty array, at most 1000 entries, sorted by unique candidate_id |
| ra_key, tally_key | objects with exactly key_id, spki, fingerprint |
| profile | string, RSABSSA-SHA384-PSS-Randomized |

Each candidate has exactly canonical UUID `candidate_id` and NFC `candidate_name`
(1..128 Unicode code points, no surrounding whitespace, controls, or lone
surrogates). Names are rejected rather than silently normalized. Each public key
entry uses the key_id syntax above, canonical base64url DER SPKI, and lowercase
SHA256(DER SPKI) fingerprint. Both RSA keys must be 3072-bit/e=65537 and distinct.
Canonical DER is checked by parse/re-serialize equality.

The authority must publish one immutable manifest per election. Future setup
must reject different manifests for the same election and signing-key reuse
across elections. Those stateful administrative controls are not implemented by
this stateless crypto gate. Rotation requires a new election/manifest. The root
authority is trusted: signature verification cannot prevent its compromise or
deliberate equivocation. The test authority is newly generated in memory; no
production/demo operational authority key is read or established by these tests.

## Privacy and storage boundaries

Client owns serial, encrypted envelope, prepared message, inverse, and final
credential. RA receives only the election/key selection and original blinded
message through an authenticated issuance flow; the present Go test transport
has only op, key selector, and blinded_msg. Voting receives the anonymous proof
and eventually the encrypted envelope, without RA identity/authentication data.

Client recovery will need encrypted storage before network issuance; this gate
keeps its state only in memory. Real key generation/provisioning, protected
signer IPC, authorization reservations, quotas, spend enforcement, election
state, encryption, and persistent recovery belong to later milestones.

Encrypted candidate-choice validity and GCM-tag validity are deferred to Tally
in this local demo. Binding an envelope hash does not prove its plaintext is a
valid choice. This protocol does not claim full anonymity against timing/IP/log
correlation, coercion resistance, receipt freeness, or full end-to-end verifiability.

## Executable evidence and gate condition

The official RFC 9474 Appendix A.1 fixture retains its original RSA-4096 key.
The driver verifies the pinned upstream fixture SHA256, reproduces its client
randomness only in the RFC test, sends the original 512-byte blinded_msg to
CIRCL, matches blind_sig and final sig, and verifies the prepared message in
Python. The separate generated test uses RSA-3072 keys and genuine fresh client
randomness. The RFC testing exception never relaxes runtime RSA-3072 validation.

Generated RSA and Ed25519 private keys stay in memory. Published RFC private
test components are downloaded to a managed OS temporary directory, never Git.
The Go test signer refuses a test-key file with a modulus other than Appendix
A.1's published modulus. Do not deploy the test signer as an RA service.

The full gate must execute the real TS -> Go -> TS -> Python path and all
negative cases. The client-only test using the published blind_sig is useful
partial evidence, **not** a replacement for running CIRCL BlindSign. Until the
full gate passes, RA issuance and Voting implementation are not ready to proceed.
